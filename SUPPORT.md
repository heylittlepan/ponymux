# Support and feedback

Start with the [getting started guide](https://ponymux.com/docs/getting-started) or [agent integration guide](https://ponymux.com/docs/integrations).

## Bugs and feature requests

Search [existing issues](https://github.com/heylittlepan/ponymux/issues) before opening a new report. If an issue matches your experience, add any new reproduction details and your PonyMux version there.

For bugs, include your PonyMux version (PonyMux → About PonyMux), macOS version, what happened, and what you expected. If the problem involves an agent, include its name and version. Intermittent bugs are welcome: describe what you were doing even if you cannot reproduce the problem reliably.

For feature requests, explain the task you are trying to accomplish and what gets in your way. You do not need to design a solution.

## Logs and crash reports

- Press `⌘⇧L` in PonyMux to open the debug log. Include only the entries around the problem, with its approximate time.
- For a crash, look for the matching PonyMux report in `~/Library/Logs/DiagnosticReports/`.
- Inspect logs, crash reports, screenshots, and recordings before attaching them. Remove credentials, private code, conversations, customer information, and personal paths. Do not upload your session database or full agent transcripts.

GitHub issues are public once this repository is public. For a security vulnerability or a report that needs private handling, email [hi@ponymux.com](mailto:hi@ponymux.com) with a short description first. Do not post sensitive details in an issue or send unredacted logs before discussing what is needed.

## Updates

Use the update button in PonyMux when a release is available, or [download the latest version](https://ponymux.com/download). The [changelog](https://ponymux.com/changelog/) lists release highlights and version downloads.
