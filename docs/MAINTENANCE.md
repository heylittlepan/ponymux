# Maintaining this repository

## Product information

- Keep the README focused on why someone would use PonyMux. Link to the website for detailed instructions.
- Keep `CHANGELOG.md` as selected public release highlights, with the website changelog as the main history. Copy only material prepared for users, without private issue links or internal release instructions.
- Check installation claims against the downloadable app. In particular, verify the architectures of the actual release binaries before claiming Intel support.
- The README image is a website demo. Its source and capture settings are in `assets/README.md`.

## Feedback

- Apply `bug` or `enhancement` labels, ask for missing reproduction details, and link duplicate reports to the original public issue.
- When a release resolves a report, reply with its version and the public release notes before closing the issue.
- Keep security reports and sensitive diagnostics out of public issues. `SUPPORT.md` describes the private contact route.

## Repository updates

- Write documentation, commit messages, and public responses in English.
- Use the repository owner's configured commit identity for publication. Verify both author and committer before pushing.
- Check the repository description, homepage, topics, issue forms, and README rendering when changing public information.
- Review staged files and pending commits for private information before publishing.
- Keep download and update links pointed at the official website. This repository does not maintain a separate binary distribution.
